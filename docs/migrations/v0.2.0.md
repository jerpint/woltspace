# v0.2.0 — Sites, Projects, and Per-Wolt Isolation

> **From:** v0.1.0
> **To:** v0.2.0
> **Breaking changes:** None. Existing wolts work as-is.

---

## What's new

### Wolt sites are live

Every rodent wolt's `wolt/site/` directory is now served at `/wolt/<name>/site/` with automatic livereload. Edit `wolt/site/index.html` and it updates in the viewport instantly. No setup needed — if the directory exists, it's served.

New wolts get a wakeup template page on creation. Existing wolts keep whatever they had.

### Projects

`wolts/projects/` is a new shared directory for apps that need their own server, dependencies, or public routes. Each project has a `woltspace.json` manifest and gets served at `/project/<name>/`.

Projects are opt-in. Wolts can suggest creating one when work outgrows a static site.

The lodge now shows project cards with start/stop controls.

### Create-wolt modal

The lodge has a proper create dialog — name input + type picker (otter/beaver/raccoon). Replaces the old blank-session flow.

### Per-wolt `.claude/` isolation

New wolts created via the modal get their own `.claude/` directory with isolated settings, skills, credentials (symlinked), and cache. The `wclaude` wrapper detects this and sets `HOME` per-wolt automatically.

**Existing wolts are not affected.** They continue using the global config. See "Optional: adopt per-wolt isolation" below if you want to migrate one.

### Type system

The `type` field in `wolt/wolt.json` now maps to specific tiers:

| Type | Model | Emoji |
|------|-------|-------|
| `raccoon` | Opus | 🦝 |
| `beaver` | Sonnet | 🦫 |
| `otter` | Haiku | 🦦 |
| `rodent` | (legacy, treated as raccoon) | 🦫 |

`"rodent"` still works. No action required.

## After updating

Pull the update and rebuild. On next boot:

1. **Skills refresh automatically** — the entrypoint copies platform skills on every boot.
2. **Trust config updates automatically** — all wolt directories get trusted.
3. **Sites start automatically** — any wolt with `wolt/site/` gets livereload.

### Check for issues

- If a wolt relied on custom skill behavior that conflicts with updated platform skills, check `~/.claude/skills/` after boot.
- If you edited files in `/workspace/woltspace/` directly, those changes are gone after rebuild (it's ephemeral). Use `/migrate-to-projects` if you need to recover work.

## Optional: adopt per-wolt isolation

If you want an existing wolt to have its own `.claude/` config (isolated settings, skills, cache):

```python
# From a Python shell inside the container:
from pathlib import Path
from wolts import setup_wolt_claude_config

setup_wolt_claude_config(Path("/workspace/wolts/<name>"), "<name>")
```

This creates:
- `.claude/settings.json` — platform hooks
- `.claude/.credentials.json` — symlink to shared credentials
- `.claude/skills/` — copy of platform skills
- `.claude.json` — trust config at wolt root

After this, `wclaude` will detect the `.claude/` dir and set `HOME` to that wolt's root, giving it fully isolated sessions.

**You don't have to do this.** Existing wolts work fine without it. This is mainly useful if you want wolts to have independent settings or skill overrides.

## Optional: update wolt.json type

If your wolt still has `"type": "rodent"`, you can update it to the specific tier:

```json
{
  "name": "mywolt",
  "type": "beaver",
  "role": "...",
  "capabilities": [],
  "description": "..."
}
```

This affects the emoji and model tier shown on the lodge. `"rodent"` continues to work (defaults to raccoon/Opus behavior).
