# v0.5.0 Migration Guide -- Projects to Apps

**What changed:** "Projects" have been renamed to "Apps" across the platform -- API routes, skills, UI labels, and internal code. The `wolts/projects/` directory is still supported as a legacy fallback.

## Why

"Project" was ambiguous -- it could mean a coding project, a work effort, or a platform app. "App" is clearer: it's a thing you build, run, and share.

## What's different

- API routes: `/projects` -> `/apps`, `/project/{name}/` -> `/app/{name}/`
- Skills: `/woltspace-projects` -> `/woltspace-apps`, `/woltspace-new-project` -> `/woltspace-new-app`
- UI labels: "Projects" -> "Apps" in the lodge and split view
- Bot tools: `list_projects` -> `list_apps`, `project` param -> `app`
- New apps are created under `wolts/apps/`

## Backwards compatibility

**`wolts/projects/` still works.** The platform discovers apps from both `wolts/apps/` and `wolts/projects/`. Existing apps in `wolts/projects/` will keep running without any changes.

## Recommended (optional)

When you're ready, move your apps to the new location:

```bash
mv /workspace/wolts/projects/* /workspace/wolts/apps/
```

This is not required -- everything works either way. The migration script does this for you if you prefer:

```bash
bash migrations/v0.5.0.sh [WOLTS_DIR]
```

## What stays the same

- **`woltspace.json`** manifest format -- no changes to the schema
- **Subdomain proxy** -- `blog.localhost:7777` still works
- **Port ranges** -- apps still use 4000-5999 (sites no longer use ports; the server serves them directly)
- **Tunnel sharing** -- same mechanism, just `/apps/{name}/share` instead of `/projects/{name}/share`
