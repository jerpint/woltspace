# v0.5.0 Migration Guide -- Projects to Apps

**What changed:** "Projects" have been renamed to "Apps" across the entire platform. This affects directory names, API routes, skills, tools, UI labels, and internal code.

## Why

"Project" was ambiguous -- it could mean a coding project, a work effort, or a platform app. "App" is clearer: it's a thing you build, run, and share.

## What you need to do

### 1. Rename `wolts/projects/` to `wolts/apps/`

```bash
mv /workspace/wolts/projects /workspace/wolts/apps
```

This is the only required filesystem change. All your `woltspace.json` manifests stay exactly the same.

### 2. Update your browser bookmarks

Old URLs no longer work. The new routes:

| Old | New |
|-----|-----|
| `/projects` | `/apps` |
| `/projects/{name}` | `/apps/{name}` |
| `/projects/{name}/start` | `/apps/{name}/start` |
| `/projects/{name}/stop` | `/apps/{name}/stop` |
| `/projects/{name}/share` | `/apps/{name}/share` |
| `/projects/{name}/unshare` | `/apps/{name}/unshare` |
| `/project/{name}/` | `/app/{name}/` |

### 3. Update `/woltspace-update` to get the latest skills

After pulling the new version, skills auto-sync on boot. The skill renames:

| Old Skill | New Skill |
|-----------|-----------|
| `/woltspace-projects` | `/woltspace-apps` |
| `/woltspace-new-project` | `/woltspace-new-app` |

### 4. Update any custom bot tools

If you have custom bot tools referencing `list_projects`, it's now `list_apps`. The `project` parameter in `claude_code` and `new_session` tools is now `app`.

## What stays the same

- **`woltspace.json`** manifest format -- no changes to the schema
- **Subdomain proxy** -- `blog.localhost:7777` still works
- **Port ranges** -- apps still use 4000-5999, sites still use 6001-6999
- **Tunnel sharing** -- same mechanism, just `/apps/{name}/share` instead of `/projects/{name}/share`

## State directory changes

| Old | New |
|-----|-----|
| `wolts/.space/projects/` | `wolts/.space/apps/` |
| Session JSON `"project"` field | Session JSON `"app"` field |

The `.space/projects/` directory (running state files) will be recreated automatically when you start apps. You can safely delete the old one:

```bash
rm -rf /workspace/wolts/.space/projects/
```

## For wolt developers

If your wolt's `memory/context.md` or `memory/learnings.md` references "projects", you may want to update those references to "apps" to avoid confusion. This is optional but recommended.
